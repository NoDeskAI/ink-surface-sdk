## 真实模型结果

服务器现有配置使用 `kimi-k2.6`。

### 19 条发言短样本

- Brief 调用：64,584 ms；Brief stage：64,596 ms。
- 生成 `summary_cards`：2,520 B；兼容摘要：1,544 B。
- 内容结构：7 个要点、3 个亮点；无未经证据支持的决策、行动项或风险。
- 相对 47,643 B 原始 Markdown，卡片缩小约 94.7%。
- Full report 调用：103,387 ms，模型返回非法 JSON，scheduler 正确进入 retry。

### 365 条发言长样本

- 首个分块调用：120,338 ms。
- 网关 HTTP 成功但正文为空，scheduler 正确进入 retry。
- 本次未继续扩跑其余长样本，避免在已确认的网关问题上重复消耗。

## 关键发现

1. 原始产物体积异常主要来自 SVG，而不是转写本身。三个样本中 SVG 占原文件约 78%–99%。后处理输入必须只传 OCR/手写语义证据，不得传内嵌 SVG。
2. V2 卡片压缩效果成立。真实短样本从 47.6 KB 降到 2.5 KB，信息入口明显更直观。
3. 当前主要延迟在模型调用。短 Brief 已需约 65 秒，Full report 约 103 秒，长会单个分块约 120 秒；本地分块、校验与存储仅为毫秒级。
4. JSON 契约稳定性不足。显式补充字段契约后 Brief 成功，但 Full report 仍会返回非法 JSON；需要网关 structured output、修复解析或 JSON repair。
5. Full report 自动生成会把用户等待时间和模型成本放大；后续产品决策已将该能力完全下线，只保留 Cards 与可读摘要。
6. 长会议目前串行处理分块；即使每个分块成功，多个分钟级调用也会线性累积，适合增加有限并发和分块缓存。

## 建议的下一步

1. 输入瘦身：在持久层拆分 `transcript / handwriting semantics / SVG render asset`，摘要链路永不接收 SVG。
2. 快速首屏：默认只运行 Brief；Full report 由用户点击后生成，并独立显示进度与失败状态。
3. 稳定输出：为网关增加 JSON Schema/structured output；保留严格校验，并增加一次受控 JSON repair。
4. 性能优化：长会议分块有限并发（建议 2–3）、复用 chunk cache、设置单调用超时并记录输入/输出 token。
5. 质量回归：固定这 5 个私有样本，持续比较端到端耗时、成功率、artifact 大小、尾部覆盖率和证据引用有效率。

- Canonical cards 现在有产品级上限；详细候选不再把快速摘要 artifact 膨胀到 15–26KB。UI 仍只展示一个概览段落、最多 5 条讨论和最多 5 条后续事项。

### 本轮落地决策

1. 完整报告完全下线；默认会议结束只生成 Cards 与可读摘要。
2. 删除完整报告执行通道、模型调用、客户端请求和 UI 状态；旧 API 返回 HTTP 410。
3. 历史报告字段与 artifact 只作读取兼容，不投影或展示；历史未完成任务恢复后取消。
4. 默认整会预算提高到 24,000 字符；只有超过安全预算的会议才进入有重叠的顺序分块。
5. 对缺少正文的空行动项做受控丢弃，避免一条无效候选触发整份会议昂贵重跑；证据引用仍保持严格校验。
6. 暂不引入主题感知分块。当前数据表明瓶颈主要是调用次数和轻微 JSON 漂移；在超长会议样本出现真实主题跨界质量问题后，再以固定回归集评估主题边界切分。
