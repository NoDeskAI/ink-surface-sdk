# 用户访谈归档纪要生成提示词

请根据我提供的用户访谈材料，生成一份完整的“用户访谈中文版归档纪要”，并输出为单个 HTML 文件。

## 输入材料

我会提供以下一种或两种材料：

1. 必选：InkLoop 自有会议证据
   - InkLoop 自己采集并收敛的完整正式转写；
   - InkLoop 板书、手写标记及 OCR 结果（如有）；
   - 不使用 Gemini、Zoom、飞书或其他第三方工具生成的自动会议纪要。

2. 可选：研究者即时见解
   - 研究者在访谈结束后记录的关键发现；
   - 对受访者工作流程的理解；
   - 产品机会、负向信号或存疑点；
   - 研究者认为应当在会议汇报中重点讲述的内容。

## 材料处理优先级

如果提供了“研究者即时见解”：

- 将这些见解放在文档最前面的“研究者即时发现”中。
- 以研究者即时见解为主要分析框架。
- 使用逐字稿补充证据、具体行为、例子和时间点。
- 在研究者见解之外，再主动从会议材料中提炼若干重要发现。
- 不要只整理研究者已经说过的内容。
- 如果研究者见解与逐字稿存在差异，保留研究者判断，同时明确标注差异、证据限制或“存疑”，不要悄悄合并。

如果没有提供“研究者即时见解”：

- 直接根据会议纪要和完整逐字稿，主动提炼 5–8 个最重要的研究发现。
- 不要停下来要求研究者先提供观点。
- 不要只复述自动摘要，要根据受访者的具体行为、工作流程和原话形成判断。
- 将提炼出的发现放在文档最前面的“研究者即时发现”中。

## 分析原则

请先完整阅读 InkLoop 自有正式转写和板书/手写证据，再进行整理。第三方自动摘要不作为输入或线索。

严格区分以下三类内容：

1. **受访者事实**：受访者明确说过、展示过或实际做过的事情。
2. **研究者判断**：根据受访者行为和工作流程得到的分析与解释。
3. **产品假设**：尚未经过真实任务、原型或更多样本验证的机会方向。

## 证据纪律与对象绑定

每一条行为或结论都必须先确认它的作用对象：

- 实体白板；
- 数字白板；
- 课程平台；
- 录像；
- 屏幕共享；
- 教师设备；
- 学生设备；
- 采购与耗材；
- 或“对象不明确”。

提问中出现 `board`，不代表回答一定仍在描述实体白板。如果回答出现 `screen`、`slide`、`tab`、`session`、平台功能等线索，不得自动把擦除、保存、复用或截图行为归到实体白板。对象无法确认时必须标记“存疑”，不能自行补全。

保留原始量词和不确定性：

- `usually` 不得改成“总是”或“从不”；
- `might`、`think`、`believe` 不得改成确定事实；
- 单次行为不得直接写成稳定习惯；
- 受访者后续自我修正时，以最终口径为准；
- “刚需、必须、无法、完全、所有、无意愿、禁止”等强断言，必须有直接原话支持。

信息来源必须分层：

1. 受访者直接陈述；
2. InkLoop 自有画面、板书或手写中的可见行为；
3. 研究者判断；
4. 产品假设；
5. 存疑内容。

没有作为本次输入提供的问卷、其他访谈、研究者记忆或第三方摘要，不得混入本场事实。

产品机会必须分级：

1. **主动需求**：受访者主动表达了问题或需求；
2. **行为支持假设**：真实行为支持该方向，但受访者没有主动提出；
3. **研究者设想**：由研究者进一步推导，证据较弱。

使用、称赞或依赖现有功能，不等于对新产品存在需求，也不等于购买意愿。

不要把研究者提出的功能写成受访者主动提出的需求。

不要因为受访者称赞某个产品概念，就写成：

- 需求已经成立；
- 产品已经得到验证；
- 受访者存在明确购买意愿；
- 该需求具有市场普遍性。

重视负向证据，包括：

- 不保存；
- 不导出；
- 不拍照；
- 不复用；
- 不整理；
- 不在意；
- 不愿改变原有流程；
- 现有平台已经满足需求；
- 某个问题从未真实发生；
- 受访者只是在研究者追问后才开始设想。

注意区分：

- 高频书写不等于高频保存需求；
- 高频擦除不等于需要自动记录；
- 使用过某种工具不等于当前高频使用；
- 可以导出不等于需要导出；
- 内容能够保存不等于受访者会主动复用；
- 多个平台之间存在信息分散，不等于教师需要个人知识库。

单一受访者的发现不能直接外推为市场比例或普遍结论。

## 重点分析的问题

以下内容只用于分析时检查是否存在重要线索，不是“完整会议纪要”的固定目录，也不是必须填满的问卷。

- 只有当某个主题在真实对话中出现时，才对它进行总结和分析。
- 没有被问到、没有谈到或信息不足的主题，不要推测、补写或强行建立小节。
- 不要为了覆盖下面的清单，把零散的一句话扩写成一个完整结论。
- 只有当“没有发生”“明确不需要”或“拒绝使用”本身构成重要负向证据时，才需要重点写出。
- 最终会议纪要的分段必须服从真实谈话内容。

### 1. 受访者画像

- 教授什么；
- 学生是谁；
- 线上、线下或混合授课；
- 一对一、一对多或班级教学；
- 是否服务自闭症、ADHD、学习障碍或其他特殊学习需求人群；
- 独立教师、机构教师或平台签约教师。

### 2. 端到端教学流程

- 如何备课；
- 谁决定教学内容；
- 是否回看上一堂课；
- 是否复用以前的材料；
- 课前是否发送内容；
- 如何布置设备；
- 课堂如何开始；
- 如何讲解和调整；
- 课后如何处理材料。

### 3. 工具与平台

- 实体白板；
- 数字白板；
- 摄像头；
- 实物投影仪；
- 平板电脑和手写笔；
- 互动显示屏；
- 视频会议软件；
- 课堂平台；
- 外部内容网站；
- 消息工具；
- AI 工具；
- 硬件和软件之间如何配合。

### 4. 白板具体工作流

- 写什么；
- 为什么写；
- 学生如何看到；
- 学生如何参与；
- 如何判断学生是否看清或跟上；
- 何时擦除、重写或重复；
- 一堂课擦除多少次；
- 板书后来是否被拍照、保存、发送或复用；
- 下一堂课能否恢复上一次的内容。

### 5. 内容流转

- 内容从哪里进入课堂；
- 是否需要导入 PDF、PPT、图片、视频或链接；
- 内容是否被保存在平台中；
- 是否需要导出；
- 是否形成教师个人资产；
- 是否按学生、日期、课程或主题组织；
- 教师以后如何重新找到。

### 6. 采购关系

- 谁提出需求；
- 谁选择产品；
- 谁批准购买；
- 谁付款；
- 购买后归谁所有；
- 公司提供什么；
- 教师自己购买什么；
- 教师是否获得报销；
- 当前行为能否支持对高价智能硬件的支付意愿。

### 7. 产品机会与限制

- 当前流程中真实存在的绕路、返工、等待和重复劳动；
- 什么问题已经被现有平台解决；
- 什么问题仍然没有解决；
- AI 白板笔可能进入哪个环节；
- 哪些产品方向在本次访谈中没有证据支持；
- 产品价值更可能发生在课前、课中、课后，还是非正式答疑场景。

## “研究者即时发现”的写法

文档最前面必须放置“研究者即时发现（优先阅读）”。

提炼 5–8 个发现，每个发现应尽量包含：

- 受访者的真实行为；
- 具体工作流程或例子；
- 为什么重要；
- 对产品方向意味着什么；
- 是正向信号、负向信号还是待验证线索；
- 证据强度与推断边界。

即时发现不要按照访谈发生顺序机械排列，而要按照会议汇报价值排序。

优先把以下发现放到前面：

- 会改变产品方向的结论；
- 明确的负向证据；
- 现有平台已经解决的问题；
- 反复出现的行为；
- 与原有产品假设冲突的事实；
- 能够在多个受访者之间形成连续信号的内容；
- 值得继续验证的新场景。

使用具体的判断标题，例如：

- “她需要平台内回看，但不需要导出或建立个人档案”；
- “实体白板是临时草稿，不是需要长期保存的课程资产”；
- “平台已经覆盖核心课堂流程，额外硬件的空间有限”；
- “保存内容的价值不只是归档，而是恢复某个学生上次的进度”。

避免空泛标题，例如：

- “技术带来了新的可能”；
- “用户体验值得关注”；
- “平台具有重要价值”；
- “AI 可以提升效率”。

## HTML 章节结构

请直接按照以下结构生成，不依赖任何外部模板。

### 一、研究者即时发现（优先阅读）

- 提炼 5–8 个最重要的发现。
- 如果提供了研究者即时见解，以其为主，再补充从逐字稿中发现的重点。
- 如果没有研究者即时见解，完全根据会议材料主动提炼。

### 二、受访者画像

包括：

- 职业与机构关系；
- 教学科目；
- 学生类型；
- 授课形式；
- 线上与线下比例；
- 当前工作方式；
- 与研究主题相关的背景。

### 三、完整会议纪要

完整会议纪要必须尊重真实对话的内容和展开方式，只对实际谈到的内容进行分段整理。

- 先按照逐字稿还原真实对话脉络，再决定如何分段。
- 小节标题必须从本次访谈实际谈到的主题中产生。
- 可以把前后分散但属于同一件事的对话合并，但不要改变受访者原意。
- 保留有研究价值的具体课程、工具、操作步骤、数字、频率、例子、时间点和支线内容。
- 没有谈到的课前、课中、课后、采购或内容保存等主题，不建立空小节，也不自行补全。
- 短答、拒绝展开或信息不足必须保持真实信息密度，不能扩写成完整故事。
- 事实总结贴近对话，产品判断统一放在“研究者即时发现”或“产品机会”章节。
- 根据实际内容设置适量小节，不规定固定数量。
- 对每个有实质内容的话题，尽量交代谈话背景、具体做法、工具或材料、实际结果及选择原因。
- 具体经历尽量保留“当时情况 → 使用什么 → 做了什么 → 学生如何反应 → 最后怎样处理”的事件顺序。
- 同一话题中的多个例子，保留能解释行为差异或决策逻辑的内容。

#### 将受访者原话放进对应的小节

- 不再单独建立“值得保留的受访者原话”章节。
- 选择最能证明行为、需求、态度或限制条件的原话，直接放在相关会议纪要小节中。
- 每个重要话题可保留 1–3 句有证据价值的原话；没有合适原话时不强行加入。
- 使用引用框展示，保留原语言并标注受访者姓名和时间点。
- 可以修正明显断句，但不得改变原意；不确定词语标记“转写存疑”。
- 不选择寒暄、礼貌回应或脱离上下文后容易误解的句子。

### 四、产品机会或对产品方向的影响

分别写清：

- 已有较强行为证据支持的机会；
- 仍需验证的机会；
- 本次访谈不支持的产品方向；
- 产品进入现有工作流需要满足的条件；
- 不能被误写成用户需求的研究者假设。

### 五、证据强度判断

使用表格，至少包含：

| 结论 | 证据强度 | 判断依据 |
| --- | --- | --- |

证据强度使用：高、中高、中、中低、低。

判断时优先考虑：

- 是否有具体行为；
- 是否有最近发生的事件；
- 是否多次出现；
- 是否有真实工具、材料或工作流支持；
- 是否只是态度表达；
- 是否由研究者诱导后才出现；
- 是否可能只是礼貌性回应。

### 六、待验证问题

分为两类：

1. 事实缺口：本次访谈没有问清楚的行为、频率、场景或工具关系。
2. 产品假设：需要在其他用户、真实任务或原型测试中验证的方向。

### 七、建议的后续动作

提出具体研究行动，例如：

- 后续访谈应增加什么问题；
- 应招募哪类用户；
- 应观察或要求用户展示什么；
- 应设计什么低保真原型；
- 应比较哪些工作流程；
- 哪些假设暂时不应继续投入。

不要写成泛泛的“继续研究用户需求”。

### 八、归档说明

明确说明：

- 这是单一受访者的定性材料；
- 不代表市场占比或普遍需求；
- 哪些内容属于受访者事实；
- 哪些内容属于研究者判断；
- 哪些内容仍然存疑；
- 哪些产品机会尚未得到验证。

## HTML 样式要求

输出一个完整、可直接打开的 HTML 文件，包含：

- UTF-8 编码；
- 左侧固定目录；
- 右侧正文；
- 米白色纸张背景；
- 深色侧边栏；
- 清晰的一级、二级和三级标题；
- 表格、引用框和存疑提示框；
- 点击目录可以跳转到对应章节；
- 支持窄屏显示和打印；
- 不依赖外部字体、图片或 JavaScript 库。

文件名格式：

`访谈日期，受访者姓名用户访谈_中文版归档纪要.html`

## 写作要求

- 使用自然、准确、可供同事快速阅读的中文。
- 不要使用宣传语言。
- 不要堆砌“赋能、闭环、沉淀、显著提升、巨大潜力”等词。
- 尽量用真实动作表达流程，例如：

  `进入学生对应的课程 → 打开上次白板 → 清除旧答案 → 更新材料 → 继续教学。`

- 对没有证据支持的方向，直接写：“本次访谈没有发现相关需求。”
- 对研究者推导出的机会，明确写：“这是研究者根据现有行为提出的假设，不是受访者主动提出的功能需求。”
- 如果逐字稿内容存在转写错误、前后矛盾或难以确认的说法，标记为“存疑”，不要自行补全。
- 不要停留在摘要层面，要形成完整、可归档、可用于内部汇报的研究文档。
